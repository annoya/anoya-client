The 180 pt ring is replaced by the pixel cat — DS local / homeHero: catStage 240×200 (cat 120, glow 240 or 260, blur 80) · 16 · status line 16/24 · 20 · primary button 200×48. The hero takes all the free space between the status strip and the cards and is centred in it. 5 · Rule editor

A rule is one match type, one action and any number of values. A thousand exceptions are one rule with a thousand domains, not a thousand rows to scroll, drag and delete one by one. The rule opens as a full page instead of a dialog: a list pasted from a site needs room, and a page keeps the keyboard from covering the field. Text values are entered as a list — one per line, or separated by commas, spaces or semicolons — so the plain-text and comma exports of iplist.opencck.org and similar sites paste in as they are; nothing is fetched by the app. Countries and GeoSite categories are picked with checkboxes. For the engine, several domains or subnets become one RULE-SET with an inline list — mihomo looks those up in an index instead of testing a thousand lines in turn; a single value stays an ordinary rule line. Keywords, patterns, processes, countries and categories are written out one line per value: they are few, and mihomo has no indexed form for them.

9 · Error messages

Two formats, and the choice between them comes down to one question: will the user have time to act on this message. Toast — for what has already happened and needs no decision (subscription refresh failed, link copied, secrets kept in a file): disappears on its own after 3 s, dismissed by tapping it, no close button — there’s no point closing manually what goes away by itself. Error dialog — for what blocks work (failed to connect, account expired, no VPN permission, unrecognised link): centred, with a scrim that intercepts taps until the message is closed with the 36 pt close button. It can’t be skipped — unlike a bar at the bottom, which is easy to overlook — and a failure reason that vanishes after three seconds is useless. Neither format takes space in the layout: the screen must not jump because of a message. The wording always has two parts: what happened and what to do about it; the technical exception text stays in the logs, not in the UI.

10 · Subscription from a panel (Marzban · 3x-ui · Remnawave)

Verified on two live Remnawave subscriptions. The panel sends far more in headers than the server list: the profile name (often in base64:), remaining traffic and expiry (subscription-userinfo), a message from the provider (announce), a support link (support-url), a human-facing page (profile-web-page-url), the refresh interval and routing rules (routing).

In return, the panel expects device identification from the client: the mandatory x-hwid plus the optional x-device-os, x-ver-os, x-device-model. It uses them to count devices against the subscription limit; with the limit enabled, a request without x-hwid gets 404, and when the limit is exceeded — x-hwid-max-devices-reached. This is not about the client name, but about being able to speak this protocol.

The boundary from ADR-005 stays: a subscription has no account. The panel doesn't tell us “this one is forbidden” — it just returns a different list. So everything that came in headers lives in a separate Details group and is labelled as their words, not as state we control. The group caption is neutral: authorship is carried by the rows themselves — the provider message has no warning icon, and under the plan figures it says “what the subscription reports, not verified here”.

14 · Connection check

The system's “connected” status means the interface is up — and nothing more. The tunnel can sit with the interface up and pass not a single byte: the AmneziaWG handshake did not complete, the VLESS server accepted TCP and stays silent, the subscription with the provider expired. From the outside it all looks the same — a happy connected cat and dead internet, and the person looks for the cause anywhere but the VPN. The check is an HTTP request through the selected server: the engine can do it itself (Proxy.URLTest, the same mechanism that url-test groups use to pick a member), and it costs a single HEAD. It runs by itself after connecting (2 s warm-up, up to three attempts 2 s apart) and on demand from Advanced.
